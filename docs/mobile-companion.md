# Web companion (Tailscale Serve)

The Web companion is an opt-in, responsive browser interface to selected CanvasTTY sessions. On narrow screens, the **Sessions** menu opens on the attention-first session list; selecting a session opens its detail, and the menu reopens to switch sessions. Wider screens keep the list and detail side by side. Its restrained colors and typography match the desktop interface. It is not an Android app and needs no mobile installation. It works in browsers on Android, iOS, and desktop devices connected to the **same tailnet** as the computer running CanvasTTY. This deployment has not yet been exercised end-to-end on Windows, Linux, or macOS release packages; verify the setup on your devices before relying on it.

## Set up

1. Install Tailscale, sign in on the CanvasTTY computer and on each client device, and enable Tailscale HTTPS/MagicDNS for your tailnet. Keep CanvasTTY running.
2. In CanvasTTY, open **Settings → Controls → Web companion**. On the host computer run `tailscale serve --bg 3481`, then `tailscale serve status`. This Serve syntax is supported by the Tailscale CLI; it proxies the HTTPS tailnet address to CanvasTTY's HTTP listener at **127.0.0.1:3481**. On Linux, if Serve reports `Access denied: serve config denied`, run `sudo tailscale serve --bg --https=443 http://127.0.0.1:3481` on the host with local admin authorization, then inspect `tailscale serve status`; never paste a sudo password into the phone or chat. Alternatively, ask an administrator to grant Serve operator access; do not change persistent privileges. Do **not** use `tailscale funnel`: Funnel exposes the service to the public Internet.
3. Enter the **exact** `https://<device>.<tailnet>.ts.net` origin shown by Tailscale, without a path, port, or trailing slash. CanvasTTY does not discover or configure Tailscale automatically. Choose which existing sessions are shared and whether the browser may send input, create sessions in the selected local workspace, or close shared sessions. Browser and filesystem access are not exposed to the Web companion. Enabling this mode moves the companion listener from LAN to loopback; Even G2's local connection is a separate, explicit choice.
4. Save and begin pairing in the desktop settings. On a tailnet-connected device open `https://<device>.<tailnet>.ts.net/mobile/`, enter the six-digit code, then **approve the displayed browser** on the computer. Codes expire after two minutes. The paired browser can then use only the granted session actions. Session creation requires an available provider CLI on the host and a desktop-selected workspace; no remote folder picker exists.

If the page does not load, check that CanvasTTY is running and enabled, `tailscale serve status` shows the correct HTTPS mapping, the hostname matches the saved origin, and the client is signed into the tailnet. A listener shown as ready in CanvasTTY does not by itself prove Tailscale Serve is configured or accessible. Avoid a public reverse proxy, port forwarding, and Funnel.

## Turn off and revoke

In Controls, **Turn off Web companion** stops CanvasTTY's listener while keeping its settings for later. **Opt out of Web companion** disables it and clears the HTTPS origin, but does not delete existing device grants. Use **Disconnect device → Revoke** for each paired browser whose access should end. Revocation removes its desktop grant; turn off or remove the Tailscale Serve mapping separately with the Tailscale CLI (inspect `tailscale serve status` first). If a phone is lost, revoke its pairing and its tailnet access. Switching to the Even G2 LAN flow requires explicitly choosing a local network; no settings change silently changes transport.

## Security and limitations

The HTTPS endpoint is tailnet-scoped, not publicly hosted; tailnet membership is **not** pairing authorization. Six-digit SRP pairing requires explicit approval on the desktop; subsequent session requests use a separate encrypted channel and desktop grants. Treat the browser profile as sensitive: pairing credentials stored in browser localStorage may remain accessible to scripts running at that origin and to anyone using an unlocked device/profile. Use a trusted device, avoid shared browser profiles, and revoke lost or compromised clients. HTTPS protects the Tailscale hop; the loopback backend is HTTP and must stay bound to 127.0.0.1. Do not publish the private desktop endpoint through Funnel or another public proxy.

The Web companion has no separate API for arbitrary filesystem operations, the desktop Browser, plugins, provider credentials, or unrestricted agent control. **Raw shared terminal output is not sanitized:** a CLI can print secrets, passwords, file contents, or credentials to its PTY, and anyone granted that session can read them. Typing into a shared terminal can also run commands under the host account. Share only trusted sessions and grant input sparingly. See [security policy](../SECURITY.md) and [architecture](ARCHITECTURE.md).

Terminal output is retained only in bounded host memory (up to 240,000 UTF-16 characters per session), not stored as durable history. After a long disconnect the browser may show a gap where older output was evicted. A desktop restart may restore session descriptors if session restore is enabled, but cannot restore prior terminal output. The browser polls about every 2.5 seconds while visible; it is not a background service or a push-notification client.

The raw xterm view displays PTY output but is not a full remote terminal emulator: input uses the text-send action and a fixed keybar (Ctrl-C, Enter, arrows, Tab, Backspace, Esc). It does not forward arbitrary key combinations, mouse gestures, paste without submission, or browser-size changes to the host PTY.
